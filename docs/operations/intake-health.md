# Read-only Source & Intake Health

`GET /v1/local/source/health` is served by the existing authenticated Core `SourceController`. All three scopes are required: `source:read`, `transactions:read`, `policies:read`. The verified token selects workspace; the app pool's configured `lmps.read_namespace` selects namespace, with the existing source-reader default `synthetic_snapshot`. Intake config selects `synthetic_csv`. Any query parameter is rejected. The OpenAPI response describes the aggregate envelope.

`readIntakeHealth` uses one read-only repeatable-read transaction for snapshot time, scoped size metadata, complete revision evidence and policy bindings/versions. It reuses `analyzeIntakeRevisionHistory`, now shared through `@lmps/database`; the worker export and CLI remain compatible. No migration, extra grant, raw staging read, policy activation, dispatch or source access is added. Native reader credentials retain their existing pool/query limits.

Chains containing file publication/provenance are selected, then every revision in each chain is validated, including mixed-provenance/latest changes. Synthetic-only records and other namespaces are excluded. The existing audit enforces at most 10,000 revisions / 64 MiB, detached JSON and recomputed publications/predecessors. Approved policy bindings must match stored version hashes and currency. The response exposes only aggregates and stored evidence reference, never raw identifiers, amounts, source clocks, policy contents or private paths.

`waiting_policy` counts latest observations without a local approved risk-policy binding. It is not a queue state, readiness result or an assessment count. Existing Detection/Sync Health remains authoritative for actual jobs, attempts and checkpoints. No disposable runner receipts are read. Source/file authority, identity, history and payment/refund semantics remain unverified; the reference hash does not authenticate the source and account slots are not unique accounts.

Size refusal returns `503 INTAKE_HEALTH_SCOPE_TOO_LARGE`; storage, integrity and transport failures return fixed `503 INTAKE_HEALTH_UNAVAILABLE`, without partial numbers/private diagnostics. Failed reads roll back, discarding a client if rollback fails. Responses are `no-store`. A valid empty scope returns zeroes with empty currency/policy arrays; outage never returns healthy zeroes.

Core acceptance: `apps/risk-api/test/intake-health.test.mjs` uses disposable PostgreSQL with v1/v2 histories, an approved LAK binding, no THB binding, synthetic records and a separate automated namespace. It checks scopes/workspace/query/method boundaries, OpenAPI, private-field withholding, limits before row fetch, corrupt policy/source evidence, mixed latest provenance, read-only snapshot isolation across a concurrent policy change, actual outage and recovery. Portal client/browser checks are documented in its `INTAKE-HEALTH-API.md`.
