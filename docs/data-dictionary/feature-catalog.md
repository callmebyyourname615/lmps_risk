# Local synthetic feature contracts v1

US-801 defines inert contracts at `@lmps/contracts/feature-catalog`. Production readiness is false. Real source identity, payment/attempt keys, lifecycle, currency/units/FX, clocks, masking, availability, owner adoption, retention and SLO gates remain pending. No earlier 15-detector catalog, B06 reference, original fixture or source semantics is changed. No graph implementation is supplied.

## APIs for US-802/803/804

`FEATURE_CATALOG_VERSION` binds catalog, policy and semantics. `FEATURE_CATALOG` lists eight supported outgoing vectors and four explicit unsupported summary families. `FEATURE_LIMITS` supplies independent absolute caps. `FeatureCatalogError.code` is fixed `FEATURE_MALFORMED` for invalid syntax/shape/semantics and `FEATURE_LIMIT` for exceeded collection/serialized limits. Errors never echo input. Unsupported evidence is well-formed data, yielding `unavailable`, never a guessed zero.

`validateFeaturePolicy(value)`, `validateFeatureDelivery(value, policy)`, `validateFeatureQuery(value, policy)`, `validateFeatureSnapshot(value, policy)`, `validateFeatureState(value)` and `validateFeatureInput(value, golden=false)` return detached JSON, throwing on unknown fields. The input bundle has exactly `{policy, deliveries, queries}`. Golden mode independently caps 32 deliveries and the entire bundle at 64KiB. Normal input/state is at most 2MiB, 2000 deliveries and eight queries; smaller policy caps apply independently. Policy includes maximum unique payments, attempts, revisions per payment and retained deliveries per account/currency key. Duplicate deliveries still occupy retained history. No truncation, eviction or ACK of an unrecorded rejection is allowed.

`detachFeatureJSON(value, maxBytes)` validates own enumerable data descriptors, ordinary object/array prototypes, dense arrays, safe integers, valid Unicode and depth <=32 before detaching. It rejects accessors, functions/toJSON, symbols, cycles, undefined, BigInt, non-enumerables and exotic prototypes. Sizes mean UTF-8 bytes of compact JSON, including all envelope fields; equality is accepted. Validators neither mutate inputs nor leak references. They do not assert caller-supplied success: there is no success flag or trusted content hash field. Snapshot `available` is a structural result union only: US-802/803/804 must recompute it from retained evidence on restore, compare exact outputs and reject forged results before use.

`featureRevisionAvailability(revision, policy)` returns the first reason in identity, coverage, lifecycle, reversal order or null when structurally supported. Missing identities are malformed; explicit `identity: unknown` with supplied synthetic placeholder IDs is unavailable. `UNAVAILABLE_REASONS` additionally covers unsupported summary, currency conflict, stale evidence, lateness and limits. `validateFeatureVector(value, signed=false)` accepts canonical nonnegative integer strings for final totals; signed=true permits explicit correction deltas (no plus sign, leading zeros or negative zero). Count and amount fields are independently bounded to 32 digits; input money is unsigned decimal with exactly two places and at most 22 whole digits. `featureMoneyMinor` converts to BigInt minor units exactly. All arithmetic downstream uses BigInt; persistence and output use canonical integer decimal strings, never floating point or JSON BigInt.

## Lifecycle and identity rules

Every ID must be explicitly supplied with `synthetic_` prefix and 1–70 ASCII alphanumeric/underscore suffix. Delivery position is contiguous zero-based lineage, never an attempt identity. Payment revision numbers are positive safe integers, ordered within a payment; `revision_id` names that declared payment revision. Attempt IDs are supplied declarations, never inferred from position, Kafka offset, revision, retry or duplicate delivery. A payment can declare several attempts. A revision's attempt ID says which attempt its attempt fields update.

For a query as_of, first exclude revisions with available_at > as_of. Select greatest revision_number per attempt for attempt_count/attempt_amount, and greatest revision_number per payment for gross/reversal/net. All selected records must have complete known evidence before arithmetic. Same payment/revision number or revision ID with different content is conflict, including an old duplicate after TTL. Attempt-to-payment/account binding and payment account, currency and occurred_at are immutable. Exact duplicate revision has no extra effect. Lower and future revisions remain in lineage; a later correction can replace or retract an earlier contribution. Different explicit attempt IDs add attempts without adding payment execution twice. Same payment currency changes produce CURRENCY_CONFLICT; no FX or cross-currency summation.

All supported vectors are outgoing per account/currency in the declared event-time window. Attempt count is one per selected attempt, including pending/failed; attempt amount is its declared request amount. Gross count is one per selected executed payment, including a declared zero execution. Gross amount is declared execution, retained through partial/full reversal. Reversed count is one per payment with positive cumulative reversal; reversed amount is cumulative, not incremental. Net amount = gross minus reversal. Net-active count is one only if net amount >0; a fully reversed or zero executed payment has net-active count zero while retaining gross execution count. Pending/failed require zero gross and cannot become executed; unknown lifecycle or reversal is unavailable even when numeric fields appear zero. For succeeded known reversal is zero; partial reversal is strictly between zero and gross; full reversal equals gross. Gross cannot exceed declared attempt amount and reversal cannot exceed gross. Explicit zero is valid evidence and differs from unavailable.

Corrections emit signed new-minus-old deltas for each separate vector and currency. Retraction removes the old vector before replacement; final counts and amounts cannot be negative. These rules are fixture declarations only, not claims about LMPS. Compare B06/reference only for overlapping executed-net semantics; attempt counts, gross counts, event-time anchor and net-active counts are intentionally distinct. Counterparty, institution, baseline and graph summaries return UNSUPPORTED_FEATURE without arithmetic or fabricated values.

## Time, state and recovery

Time is supplied UTC evidence, exact `YYYY-MM-DDTHH:mm:ssZ` with real calendar validation, no offsets/leap seconds/normalization or wall clock. Policy binds exact run, namespace, input identity, version, 1–32 unique ordered currency buckets, occurred_at anchor, coverage_start, initial watermark, lateness, TTL, freshness and all bounds. Existing state must retain the identical canonical policy. No Date.now, arrival-time or position-based completeness inference.

Window membership is `(as_of - window_seconds, as_of]`; available_at equality is eligible. Queries require as_of <= supplied watermark. Coverage must reach window start or yield COVERAGE_INCOMPLETE. Lateness rejects occurred_at < watermark - allowed_lateness_seconds; equality is admitted. Watermark is explicit and nondecreasing. Future records can be retained but are invisible until both occurrence and availability are eligible. Freshness is unavailable when as_of - watermark_of_evidence > freshness_seconds; equality is fresh. Snapshot evidence watermark is recorded with each frozen query; downstream operators must verify coverage/freshness from supplied evidence rather than use historical arrival.

TTL must be at least window+lateness. Derived active entries expire only when watermark > occurred_at + active_ttl_seconds; equality remains active. Expiry never deletes frozen snapshots, positioned replay/dedup history or old conflict detection. Total retained history has independent record, unique key, revision and byte caps. On exceeding any cap, fail without changing committed cursor/state; no successful silent eviction. Frozen query IDs are unique; at most eight snapshots. Restore must replay all retained deliveries, recompute active entries, totals, snapshot evidence and hashes, compare canonical policy and reject missing/corrupt recovery evidence. Structural state validation alone does not certify these dynamic invariants. US-802 implements algebra; US-803 implements watermark/TTL and semantic restore; US-804 owns durable atomic publication. None is implemented here.

## Canonical bytes and grouped hashes

`canonicalFeatureJSON(value)` first detaches/validates JSON, recursively sorts object keys by JavaScript UTF-16 lexicographic order, preserves array order, and emits compact JSON.stringify encoding without whitespace/newline or Unicode normalization. `featureGroupedHash(groups)` computes lowercase SHA-256 hex of UTF-8 canonical `{domain: FEATURE_CATALOG_VERSION, groups}`. Each group is one complete typed JSON value; ordering and boundaries are preserved as JSON array elements, not ambiguous concatenation. `featurePolicyIdentity(policy)` is the hash with exactly one validated policy group. Hashes are recomputed locally; a caller hash never replaces validation. Input/state size caps cover the complete ordinary serialized envelope, independent of hash length. No real values or secrets belong in this fixture surface.
