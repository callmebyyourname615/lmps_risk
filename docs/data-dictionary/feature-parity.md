# Local synthetic point-in-time parity contract v1

The additive `@lmps/contracts/feature-parity` subpath is IO-free and inert. It does not change the original replay, Python/TS reference engines, fixtures or semantics. Real eligible historical data, source and owner approval, stable identity/masking, lifecycle/units, legal retention and production adoption remain open gates. Final snapshots do not establish historical availability. `production_ready` is always false.

APIs: `validateFeatureParityPlan`, `validateFeatureParityInput` return detached strict JSON; `serializeFeatureParityPlan/Input` return canonical JSON; `featureParityPlanHash/InputHash` return SHA256. `selectFeatureParityCohort(plan,input,queryId)` returns selected lineage, eligibility and cohort hash. `compareFeatureParity(plan,input,online,offline)` returns count/hash/status summaries. `validateFeatureParityReport` and `serializeFeatureParityReport` require all five inputs and recompute the report, rather than trusting caller status. Errors have fixed `PARITY_INVALID` or `PARITY_LIMIT` codes and never include raw input.

Plan/input envelopes bind `local-synthetic-parity-1` and `local_synthetic`. The plan binds the exact input digest, Python and TypeScript runtime versions, source/compiled hashes, all four semantic versions, fixture clock and retention seconds. These declarations require independent runtime verification; even a matched report has `pending_independent_runtime_verification` acceptance. Caller hashes and success flags cannot authorize a runtime pass.

Each ordered query binds synthetic key, ISO currency, `as_of`, explicit event-time anchor, window seconds and an explicitly enumerated, unique, lexically sorted cohort of event IDs. This is fixture coverage only, never historical completeness. An empty declared cohort can produce valid zero; a missing declared member cannot. Unknown identity/currency is rejected rather than grouped. Currency changes for the same event identity are rejected; no FX or cross-currency aggregation exists.

Lineage contains synthetic event/key IDs, source position, revision, occurred time, nullable historical `available_at` plus nullable availability-evidence SHA256, record SHA256, exact unsigned decimal amount with two fractional digits and lifecycle active flag. Source positions and per-event revisions are unique, nonnegative safe counters. An adapter must independently verify record/availability hashes against private immutable evidence. They are commitments, not proof that historical availability was known. Never publish raw records or selected lineage in public status.

Selection first restricts explicit key/currency/members, excludes revisions available after `as_of`, then chooses the highest eligible revision per event, independent of input arrival order or final snapshot revision. Equality at `available_at == as_of` is eligible. Missing availability on any member revision conservatively makes that query unavailable. A member with no historically eligible revision is unavailable. Only after revision selection is the event-time window applied: `(anchor - window_seconds, anchor]`. Thus a correction that moves an event outside the window removes its prior revision, while a future correction cannot alter the earlier result. Inactive selected revisions contribute no count/amount. All arithmetic uses integer minor units via BigInt, without floating point.

Supported semantics are exactly `FEATURE_PARITY_SEMANTICS`: active count and amount sum, latest eligible revision, explicit occurred-time open-start/closed-end window, known availability. Other versioned semantics remain unsupported. No inference about original engine feature compatibility is made here. Both observations must match the complete query, cohort digest, input/plan hashes, semantic and runtime bindings. Binding differences are mismatch. Unsupported, retrospective and unavailable observations remain separate statuses with null numeric values. Numeric comparison requires eligible supported matched cohorts; both values must also equal the exact declared synthetic cohort calculation. This is a contract consistency check, not cross-runtime execution evidence.

Canonical JSON recursively sorts object keys, preserves array order, uses JSON string escaping and UTF-8 without whitespace; hashes are lowercase 64-hex SHA256. Plan/input hashes cover the complete validated envelopes. Cohort hashes cover `{query, records}` with selected records ordered by ASCII synthetic event ID, including source positions, revisions and availability evidence. Reordering an input changes its input commitment but not the selected cohort. Changing an excluded future revision still changes the exact input commitment. Runtime reports contain only query IDs, selected counts, hashes and statuses; queries and inputs stay private.

Limits: 2000 records, 2000 distinct keys, 2000 explicit members per query, 8 queries, 2 MiB UTF-8 per detached argument. There is no truncation. Windows/fixture retention are explicit positive safe seconds up to 31536000; timestamps must be real UTC whole-second dates. Amounts have up to 24 integer digits, aggregate observations up to 28, and counts at most 2000. Version strings are bounded; decimals disallow exponent notation, signs and leading zeros. Exact shapes reject unknown fields, prototypes, proxies, accessors, symbols, cycles, sparse arrays and lossy JSON. No getters or toJSON execute. Outputs share no mutable references with caller inputs.

This story starts no processes, writes no evidence and performs no native trials. Subsequent adapters must enforce private immutable evidence publication, independent actual execution verification, source/runtime provenance and owned cleanup. The broader baseline remains at most 2 GiB owned scratch, 16 MiB retained acceptance evidence and 180 seconds per independent native trial with teardown reserve. This contract does not close engine/cache/identity/legal/retention/RPO/RTO/SLO gates. Host scoped publication/source-plan/promotion verification remains pending; no status tracker or original plan checkboxes are changed by this story.

Candidate checks actually run: contracts typecheck, build, generated-artifact consistency, eight new parity test groups and the full contracts suite (204 passing tests). Package self-import through the exact additive subpath also passed. Independent host publication, policy/source-plan/Git guards, promotion receipt and later actual cross-runtime acceptance remain pending. The status tracker is outside this story's allowed files and is left for the trusted host handoff.
